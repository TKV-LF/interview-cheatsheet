data.keys()
data.values()

learners.add("Learner-0001")  # still size 1

When to use a set: counting unique people. Same learner completing a course twice is still 1 learner.
When a dict explodes: d[key] += 1 crashes if key is new. Use defaultdict or d.get(key, 0).

4. How to resolve — paper first, then code

Every Go1 challenge has the same issue: the data is grouped one way, the question is about another way. You cannot look at the JSON and type the answer. You build a small table in the middle, then read the answer from that table.

In the interview, say this out loud before typing: “I’ll build X, then I’ll pick Y from it.” That is the solution. The Python is just filling the table.

Challenge 1 — Learners and Courses

What they give: each learner, and the courses that person finished.

What they want: courses that only one person has finished.

The issue: you cannot answer from one learner. Learner-0001 finished three courses — that does not tell you if anyone else also finished them. You must flip the map: from “who did what” to “who did this course.”

Step 1 — write the input as two lists

Learner-0001 : Course-0001, Course-0002, Course-0003
Learner-0002 : Course-0002, Course-0003, Course-0004

Step 2 — empty table: course → people

Walk every pair (learner, course). Add the learner into that course’s set.

You seeTable becomes
0001 did Course-0001Course-0001 → {0001}
0001 did Course-0002Course-0002 → {0001}
0001 did Course-0003Course-0003 → {0001}
0002 did Course-0002Course-0002 → {0001, 0002}
0002 did Course-0003Course-0003 → {0001, 0002}
0002 did Course-0004Course-0004 → {0002}

Step 3 — keep size == 1

CourseLearnersCountKeep?
Course-0001{0001}1yes
Course-0002{0001, 0002}2no
Course-0003{0001, 0002}2no
Course-0004{0002}1yes

Answer: ["Course-0001", "Course-0004"]

The trap (dataset 4)

Learner-0001 lists Course-0001 twice. If you count listings (+= 1), Course-0001 becomes 2 and you drop it. Wrong. Count people with a set. Adding “0001” twice still leaves {0001}, size 1.

# Python that matches the table
from collections import defaultdict

def unique_courses(data):
    table = defaultdict(set)          # course → set of learners
    for learner, courses in data.items():
        for course in courses:
            table[course].add(learner)  # Step 2
    answer = []
    for course, people in table.items():
        if len(people) == 1:            # Step 3
            answer.append(course)
    return answer

If they say “also show courses with at least 2 learners,” change only Step 3 to len(people) >= 2. The table stays.

Challenge 2 — Quiz Results

What they give: the answer key, plus each learner’s answers (one row per person).

What they want: which question most people got right (its index).

The issue: a row is one learner’s whole quiz. The question is not “who scored highest.” It is “which column was easiest.” Look down each column.

Step 1 — write columns

index:           0    1    2
correct:         A    B    C
learner 1:       A    B    B
learner 2:       C    B    C
learner 3:       A    B    C
learner 4:       B    B    A
learner 5:       A    B    C

Step 2 — count matches per column

QuestionCompare toHitsCount
index 0AA, C, A, B, A → A A A3
index 1BB B B B B5
index 2CB, C, C, A, C → C C C3

Step 3 — biggest count wins

5 is the max → index 1. Output: The easiest question is index 1

def easiest_question(answers, responses):
    n = len(answers)
    counts = [0] * n              # Step 2: one box per question
    for row in responses:         # each learner
        for i, ans in enumerate(row):
            if ans == answers[i]:
                counts[i] += 1
    best = 0
    for i in range(n):            # Step 3
        if counts[i] > counts[best]:
            best = i
    return f"The easiest question is index {best}"

Follow-up: hardest question = smallest count (index 3 on dataset 3). Tie: ask them, or take the first index.

When you paste dataset JSON, delete the // Correct Answers comment lines. JSON cannot have comments.

Challenge 3 — Watched Courses

What they give: sessions. Each session is an ordered list of courses a person watched.

What they want: for each course, which course is most often immediately next.

The issue: the last course in a session has no next. You only care about neighbors: (item 0, item 1), (item 1, item 2), …

Step 1 — cut a session into arrows

["Course_001", "Course_002", "Course_003", "Course_004"]

001 → 002
002 → 003
003 → 004
004 → (nothing)

Step 2 — count arrows

One session is enough for the example: each arrow appears once, so the “most common next” is just the only next.

CourseNext countsWinner
Course_001Course_002: 1Course_002
Course_002Course_003: 1Course_003
Course_003Course_004: 1Course_004

Dataset 2 has several sessions. You add all arrows into the same table. If Course_001 → Course_002 once and Course_001 → Course_003 once, that is a tie. Say your rule: first one you saw, or alphabetical. They care that you noticed.

from collections import defaultdict, Counter

def most_common_next(sessions):
    table = defaultdict(Counter)   # course → {next: count}
    for session in sessions:
        for i in range(len(session) - 1):   # stop before last
            current = session[i]
            nxt = session[i + 1]
            table[current][nxt] += 1
    answer = {}
    for course, counts in table.items():
        winner = counts.most_common(1)[0][0]
        answer[course] = winner
    return answer

range(len(session) - 1) is the trick: for 4 courses, i = 0,1,2 only. Index 3 has no next.

Challenge 4 — Concurrent Learners

What they give: streams: [user, start, end].

What they want: the maximum number of streams that overlap at the same time.

The issue: looking at one stream is not enough. Overlap is about the timeline. Two streams overlap if one starts before the other ends.

["User_001", 0, 1000]
["User_002", 500, 2000]
["User_003", 2500, 3000]
["User_004", 400, 1400]

time:  0      400  500       1000  1400     2000    2500  3000
U1     |----------------------|
U4            |---------------------|
U2                 |--------------------------|
U3                                                  |------|

At t=500, U1, U2, U4 are all on → 3. U3 is later, alone. Answer is 3.

How to resolve without drawing (sweep)

Turn every stream into two events: start = people +1, end = people −1. Sort by time. Walk left to right. Remember the highest “people currently watching.”

def max_concurrent(streams):
    events = []
    for user, start, end in streams:
        events.append((start, +1))
        events.append((end, -1))
    events.sort()   # time first; -1 before +1 at the same time
    current = 0
    peak = 0
    for time, delta in events:
        current = current + delta
        if current > peak:
            peak = current
    return peak

def max_concurrent_unique_users(streams):

        if open_streams[user] == 0:
            del open_streams[user]
        peak = max(peak, len(open_streams))
    return peak

Traps: (1) same user can have two streams — count streams, not users. Dataset 4 max is 4. (2) If one ends at 1000 and another starts at 1000, usually not overlapping: put −1 before +1 when times are equal (events.sort() already does that because −1 < +1).

Follow-up: “At what time was the peak?” Save time when you update peak. “Unique users?” Keep a set of active user ids instead of a number.

Learners and Courses — easiest, safest pick

Return course IDs completed by exactly one learner.

Example: Learner-0001 did 1,2,3. Learner-0002 did 2,3,4. Output: ["Course-0001", "Course-0004"].

Ask before coding

  • If one learner lists the same course twice, is that still one learner? (Yes. Dataset 4 does this.)
  • Does output order matter?

Two steps

1) Invert: course → set of learners. 2) Keep courses whose set size is 1.

challenge.py
import json
from collections import defaultdict

raw = """
{
  "Learner-0001": ["Course-0001", "Course-0002", "Course-0003"],
  "Learner-0002": ["Course-0002", "Course-0003", "Course-0004"]
}
"""
data = json.loads(raw)

def unique_courses(data):
    course_to_learners = defaultdict(set)
    for learner, courses in data.items():
        for course in courses:
            course_to_learners[course].add(learner)
    return [c for c, people in course_to_learners.items() if len(people) == 1]

print(unique_courses(data))
# ['Course-0001', 'Course-0004']

Complexity: O(n) over every course listing. Space O(unique courses).

Quiz Results — easy

Return the index of the easiest question = the question most learners got right. 0-based (example says index 1).

Walk the example out loud: correct ["A","B","C"]. Column 0 has 3 correct, column 1 has 5, column 2 has 3 → index 1.

Ask before coding

  • If two questions tie, first index, last, or either?
  • Paste JSON without the // comments from the data file.
import json

answers = json.loads('["A", "B", "C"]')
responses = json.loads('''
[
  ["A", "B", "B"],
  ["C", "B", "C"],
  ["A", "B", "C"],
  ["B", "B", "A"],
  ["A", "B", "C"]
]
''')

def easiest_question(answers, responses):
    n = len(answers)
    correct = [0] * n
    for row in responses:
        for i, ans in enumerate(row):
            if ans == answers[i]:
                correct[i] += 1
    best = max(range(n), key=lambda i: correct[i])
    return f"The easiest question is index {best}"

print(easiest_question(answers, responses))

Watched Courses — medium, ties are the point

For each course, the most common next course across sessions. Last item in a session has no next.

Ask before coding

  • Ties? Datasets 2, 3, 4 all have them. Say: “I’ll take first-seen / most_common order unless you want alphabetical.”
  • Is Course_001 → Course_001 a valid transition? (Dataset 4. Yes, unless they say skip.)
  • Courses that never have a next: omit them (matches the example).
import json
from collections import defaultdict, Counter

sessions = json.loads('''
[
  ["Course_001", "Course_002", "Course_003", "Course_004"]
]
''')

def most_common_next(sessions):
    transitions = defaultdict(Counter)
    for session in sessions:
        for current, nxt in zip(session, session[1:]):
            transitions[current][nxt] += 1
    return {
        course: counts.most_common(1)[0][0]
        for course, counts in transitions.items()
    }

print(most_common_next(sessions))
# {'Course_001': 'Course_002', 'Course_002': 'Course_003', 'Course_003': 'Course_004'}

Dataset 2 by hand (good talking exercise):

  • Course_001 → 002 once and 003 once → tie
  • Course_002 → 003 twice → Course_003
  • Course_003 and Course_004 → all nexts appear once → ties

They care that you noticed the tie, not which rule you picked.

Concurrent Learners — hardest, most “CS”

Maximum number of overlapping streams. Count streams, not unique users. Dataset 4 has the same user on two streams at once.

Example timeline for dataset 2 (max = 3):

0         400  500        1000   1400      2000     2500
U1 |----------------------|
U4      |----------------------|
U2           |---------------------------|
U3                                               |------|
         overlap of 3 ───────────

Ask before coding

  • If one ends at 1000 and another starts at 1000, do they overlap? Usually no — process end events before start events at the same time.
  • Same user, two overlapping streams → count 2?

You may start with “for each stream, count how many others overlap” (O(n²)). Then say you can sweep.

import json

streams = json.loads('''
[
  ["User_001", 0, 1000],
  ["User_002", 500, 2000],
  ["User_003", 2500, 3000],
  ["User_004", 400, 1400]
]
''')

def max_concurrent(streams):
    events = []
    for _user, start, end in streams:
        events.append((start, 1))   # start = +1
        events.append((end, -1))    # end   = -1
    # sort by time; at the same time, -1 before +1
    events.sort(key=lambda e: (e[0], e[1]))
    current = peak = 0
    for _time, delta in events:
        current += delta
        peak = max(peak, current)
    return f"The maximum number of concurrent streams is {peak}."

print(max_concurrent(streams))
# The maximum number of concurrent streams is 3.

How the sort key works: event is (time, delta). delta is -1 or +1, so at time 1000 the end (-1) comes before the start (+1). They do not overlap.

8. Follow-ups — keep the same helper

After the first version works, they change the spec. Extend. Don’t start over.

Learners — top K, or at least N

def courses_with_at_least(data, n):
    m = invert(data)  # same course → set(learners)
    return [c for c, s in m.items() if len(s) >= n]

def top_k(data, k=3):
    m = invert(data)
    ranked = sorted(m.items(), key=lambda x: -len(x[1]))
    return [(c, len(s)) for c, s in ranked[:k]]
