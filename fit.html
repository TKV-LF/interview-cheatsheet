Tell me about yourself.

I’m Thuy, a backend and full-stack developer with about five years of experience. Most of my work is TypeScript, Node.js, PHP, APIs, databases, and getting things into production — CI/CD and cloud, not only the feature itself.

Recently I’ve been on client work and with Akktis, a France-based company. The work changes a lot, so I’m used to picking up a new system, asking the right questions, and owning the path from build to deploy to support.

The project I care most about is an IELTS AI Tutor app — now live on the Play Store and the App Store, around 5,000 users and growing about 900 to 1,000 a month. When we started, my backend and web were stronger than my mobile and CI/CD. I used LLM tools to learn React Native, store builds, and the pipeline, then I still had to understand and ship it. I also built the AI features in the product — chat, text-to-speech, speech-to-text — and used Langfuse so we could see what the model actually returned.

Before that, at BaseVN I worked on large HR, payroll, and recruitment SaaS. That taught me how messy real data is when several systems have to stay in sync.

I’m looking for a product team where I can keep building useful learning software, work closely with other strong engineers, and go deeper on AI features that have to be reliable for real users. That is the kind of product team I want next.

Gần đây tôi làm việc khách hàng và với Akktis, công ty ở Pháp. Việc đổi nhiều, nên tôi quen nhận một hệ thống mới, hỏi đúng câu, và chịu đường từ build tới deploy tới support.

10Tool walkthroughStack I can defend

Walk me through your DevOps tool stack.

Source control is Git. CI is Cloud Build or a generic CI runner on push and tags — build, test when we have them, package artifacts. For backends I Dockerize, push to Artifact Registry, and deploy Cloud Run with env and secrets, often wired to Cloud SQL and Cloud Storage. For mobile, React Native builds produce Android AAB/APK and iOS IPA concepts with signing material kept in secrets, then artifacts go to storage or store tracks. For classic web I SSH into Ubuntu/Debian, manage LiteSpeed or Apache or Nginx, firewall and TLS, and keep short runbooks. Day to day observability is Cloud Logging on Run and system/web logs on VMs.

Hãy mô tả stack DevOps của bạn.

Source control là Git. CI là Cloud Build hoặc CI runner generic theo push và tag — build, test khi có, package artifact. Backend tôi Dockerize, push Artifact Registry, deploy Cloud Run với env và secret, thường wire Cloud SQL và Cloud Storage. Mobile, build React Native ra AAB/APK Android và khái niệm IPA iOS, signing nằm trong secret, artifact lên storage hoặc store track. Classic web tôi SSH Ubuntu/Debian, quản LiteSpeed hoặc Apache hoặc Nginx, firewall và TLS, giữ runbook ngắn. Observability hằng ngày là Cloud Logging trên Run và system/web log trên VM.

12Akktis day-to-dayWhat ops looks like

What does a typical ops-heavy day look like for you?

It depends on the project, but usually I'm either unblocking a release or keeping an environment healthy. That means checking CI status for web or mobile, SSH into a Linux box to read logs or restart a service, verifying a Cloud Run revision after deploy, or fixing env and connectivity to Cloud SQL or Storage. I also touch LiteSpeed or Apache when a PHP or CMS site misbehaves, and I update docs when I find tribal knowledge that would hurt the next person.

Tùy project, nhưng thường tôi hoặc unblock release, hoặc giữ env healthy. Tức là check status CI web hoặc mobile, SSH vào Linux đọc log hoặc restart service, verify revision Cloud Run sau deploy, hoặc fix env và connectivity tới Cloud SQL hay Storage. Tôi cũng đụng LiteSpeed hoặc Apache khi site PHP/CMS lỗi, và update docs khi gặp tribal knowledge — dễ hại người sau.

13Weakness (honest)Time-box vs polish

What's a weakness relevant to this job?

I can over-invest in polishing a pipeline or runbook when a smaller safe mitigation would unblock the team sooner. I've learned to time-box: ship the safe fix or rollback first, communicate status, then harden the checklist so we don't pay twice.

Một điểm yếu liên quan job này?

Tôi đôi khi invest quá nhiều để polish pipeline hoặc runbook trong khi một mitigation nhỏ an toàn đã unblock được team. Tôi đã học time-box: ship fix an toàn hoặc rollback trước, báo status, rồi harden checklist để không trả giá hai lần.

Why did you leave BaseVN? What is the biggest technical strength on this CV?

During the time I was there, the company’s direction focused more on other product lines. On the HRM suite I was in, there was less room to grow. At the same time I wanted to try a different environment — a global outsourcing setup, with international clients and different ways of working. That is why I moved to Akktis.

After about two years at Akktis I learned a lot: Linux, CI/CD, cloud, client delivery across time zones. But I also realized what I miss. I want to build a product again — stay close to users, work with product and design, and own outcomes over time, not only project after project. That is why IELTS AI Tutor mattered to me, and why a product company feels like the right next step.

Biggest technical strength on this CV: I can follow a problem across layers and still care about the product outcome. A slow tax screen might be a query, a missing index, or a job that should not be in the request. A weird AI answer might be the model or the workflow. I debug with evidence — EXPLAIN, logs, Langfuse — then I leave the path clearer for the next person.
